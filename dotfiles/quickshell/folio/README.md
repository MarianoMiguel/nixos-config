# Folio shell

The desktop shell for the Folio design language: a Quickshell config that
replaces DMS surface by surface. The workshop's studies
(`workshop/studies/*/v*.html`, served by `scripts/workshop open`) are the
specification; `workshop/studies/_kit/folio.css` holds the same tokens as
`Common/Theme.qml`.

## Layout

| Path | What |
|---|---|
| `shell.qml` | Root. Loads `Modules/<Name>/<Name>.qml` for each name in `modules`, each on its own `LazyLoader`, so one broken module costs only itself. `FOLIO_MODULES=A,B` loads only those. |
| `Common/` | `Theme` (tokens, motion), `Settings` (Folio's preferences, `~/.config/folio/settings.json`), `Icons` (generated by `scripts/folio-icons` from the kit), spring presets `SpringPanel`, `SpringPress`, `SpringSoft`, and `Ease`. |
| `Widgets/` | `Icon`, `Label`, `Cap`, `Sheet` (the material), `Marquee`, `Plate` (the dither shader), `BlurNudge`, and keyboard focus: `KeyNav`, `FocusRing`, `PointerWatch`. |
| `Services/` | Singletons over the system: `Niri`, `Audio`, `Brightness`, `Battery`, `Power`, `Media`, `Network`, `Bluetooth`, `Tailscale`, `Privacy`, `Notifs`, `Focus`, `Toasts`, `Apps`, `DefaultApps`, `Session`, `Art`, `Outputs` (displays and their layouts), `NightLight` (and inverted colors), `Input` (keyboard and pointer, `folio-input.kdl`), `Drives`, `About`, `Sounds` (interface sounds, synthesized by `scripts/folio-sounds` into `sounds/`), `Sys` (commands that change the system; dry-run in the harness), and more. |
| `Modules/` | One folder per surface. |
| `shaders/*.frag` | GLSL 450; `scripts/folio-harness run` and the Nix package compile them to `.qsb` (git-ignored). |

`shell.qml` imports `qs.Common`, `qs.Services` and `qs.Widgets`: Quickshell
only registers folders it reaches by import from the root, and modules load
by URL. A module may use the other files in its own folder by type name: the
harness and the Nix package write a `qmldir` into each module folder (git
ignores it). Without one, sibling types resolve only by luck.

## Running and testing

Never test against the live desktop. The harness runs a headless sway with its
own runtime directory and D-Bus; services read the real PipeWire, UPower,
NetworkManager and BlueZ (do not change volume or toggle radios in tests).

```sh
export FOLIO_HARNESS_DIR=$XDG_RUNTIME_DIR/folio-harness-<you>   # one per person/agent
scripts/folio-harness start                  # 1920x1200; start 1440x900 for a smaller screen
scripts/folio-harness run "Wallpaper,Bar"    # compile shaders, start the shell, print warnings
scripts/folio-harness ipc bar fixture stress # drive a module over IPC
scripts/folio-harness shot /tmp/x.png        # screenshot (read it to check)
scripts/folio-harness key -k Escape          # keyboard; click X Y for the pointer
scripts/folio-harness restart "Wallpaper,Bar"
scripts/folio-harness stop
```

A missing import fails silently inside a binding (the value just stays
empty, nothing is logged): import `qs.Services` in every file that uses a
service, `qs.Common` for Theme and Settings.

The headless seat has no pointer device: `click` and `hover` are unreliable,
so give every interaction an IPC path for tests (fixtures, show, open) and
check real clicks on a real session. `key` works (it taps Shift first,
because wtype drops the first key of each call).

`FOLIO_MODE=dark` and `FOLIO_INK=cobalt` pin the theme for a run (set them in
the environment before `run`). QML timers need a window on screen, so load
`Wallpaper` with any module that has none. `console.warn` shows in the log;
`console.log` does not.

## Module contract

- Root type `Scope`, file `Modules/<Name>/<Name>.qml`; add the name to
  `modules` in `shell.qml` only when it works.
- Layer-shell windows use namespace `folio:<name>` and set
  `BackgroundEffect.blurRegion` (from `Quickshell.Wayland`) to the sheets they
  draw, with the sheet's radius, so niri frosts what is behind them. Add a
  `BlurNudge` keyed on whatever changes the region and add its `extra` to the
  radius: niri 26.04 sometimes drops a region that arrives while the surface
  keeps redrawing, and sending it again makes it stick. Empty a region by
  clearing its `item`, never by swapping the region for `null`.
- Each module has an `IpcHandler` with target `<name>` (lowercase), at least
  the actions its keybinds need, plus `fixture(name)` taking `normal`,
  `stress` and `empty` where it shows content, so tests can drive every state.
- Shared logic goes in `Services/` (new files are fine); never change another
  module, and change `Common/` or `Widgets/` only by adding files.
- A module folder must not share a name with a service or a Common type
  (`Battery`, `Settings`, `Displays`…): the folder's generated `qmldir` would
  shadow the singleton inside the module.
- Anything that changes the machine (connect, pair, set a default, mount,
  write a niri include) goes through `Sys.run(cmd)` or is skipped when
  `Sys.harness` is true, so tests never touch the real system. Files a
  service writes live under `$XDG_RUNTIME_DIR` in the harness (its own).
- Keyboard first: focusable controls set `activeFocusOnTab`, pass key
  presses to `KeyNav.press(event, act)` and draw a `FocusRing`, which shows
  only after keyboard use (`PointerWatch` hides it again on pointer use).
- Input masks: `mask: Region { item: someItem }` works; a `Region` with only
  x/y/width/height swallows all input. `Region {}` is click-through.

## Settings

`Modules/SystemSettings` is the Settings app (Mod+Comma): one window, a page
per area (Appearance, Displays, Sound, Network, Bluetooth, Power & battery,
Keyboard, Mouse & touchpad, Notifications, Accessibility, Default apps,
Storage & drives, About),
listed with search keywords in `SystemSettings.qml`. A page is a
`SettingsPage` file in that folder (`DisplaysPage.qml`, `SoundPage.qml`…),
built from the kit beside it: `Section` (heading and hint), `Card` (a group of
rows), `SettingRow` (a setting with a control), `ListRow` (a device, network,
layout), `Toggle`, `Choice`, `Slider`, `Button`, `Field`, `Notice` (empty and
unavailable states), `OptionCard`. `page.mark("id", item)` lets Settings open
the page at a section. `Shell.openSettings("sound")` or
`qs ipc call settings open sound` opens a page; `settings dryrun` lists the
commands pages would have run in the harness.

Files Folio writes for the system: `~/.config/niri/folio-outputs.kdl`
(displays; niri reads it through `shell-outputs.kdl` while Folio is the
shell), `~/.config/niri/folio-input.kdl` (keyboard, mouse, touchpad),
`~/.config/folio/displays.json` (layouts per set of displays),
`~/.config/folio/notifications.json`, and `~/.config/mimeapps.list` (default
apps). Everything else is `~/.config/folio/settings.json`.

The launcher (Mod+Space) searches apps, their actions, system actions and
every Settings page, and also takes prefixes: `f ` files in the home folder,
`:` emoji, `clip ` clipboard history; it answers sums and unit conversions
("5 km in mi") as you type.

Each area's service carries an `IpcHandler` with a `fixture(name)` (`normal`,
`stress`, `empty`, and `off` or `unavailable` where that exists) so its page
can be tested in every state without the real device.

## Design rules (from the studies)

- Tokens only: colors, radii, type and durations come from `Theme`. No
  literal colors except app-provided imagery.
- Motion: anything that can be interrupted (sizes, positions, opacity of
  panels) moves on a spring (`Behavior on x { SpringPanel {} }`), so a
  reversal keeps its velocity. `Ease` only for moves that always finish.
  Every exit mirrors its entry: panels leave by the edge they came from, the
  island collapses into itself, toasts sink back under the dock.
- Develop (dot-by-dot print) for first appearances only; frequent actions stay
  quick. `Plate` is the only full-screen effect.
- Radii nest: inner radius = `Theme.inner(outer, padding)`.
- Every text slot says what it does when long: `Label` elides; titles that are
  being watched use `Marquee`; bodies set `maximumLineCount`. Layouts give
  text items `Layout.fillWidth: true` with `Layout.minimumWidth: 0`.
- Every content surface has Normal, Stress (90-character titles, 99+ counts,
  many items) and Empty states, checked in light and dark.
- App icons, album art and avatars stay as shipped
  (`Settings.get("dock.icons")` may plate or print them).
- No "are you sure?": destructive actions use `Toasts.undo(...)`, final
  actions `Toasts.countdown(...)`; sleeping always locks first
  (`Session.lockThen`).
- No dithered panel over a dithered plate without the blur behind it.
