# Omarchy 4.5 rc1 + rc2 review (2026-10-28)

Read: the release notes of v4.5.0-rc1 (2026-10-20) and rc2 (2026-10-27), and
the `quattro` branch of omacom/omarchy (MIT), including `shell/` and the
theme and background scripts in `bin/`. Watermark advanced to v4.5.0-rc2. The
ideas worth judging are on the taste board with `from: omarchy`.

## What changed in 4.5

- **One Appearance menu** for theme, background, font, menu bar, windows
  (gaps, corners, opacity), branding, dock, per-workspace layout, animations
  and the unlock screen. Top-level in rc2.
- **Notifications rebuilt:** stacked by sender, actions, codes and links on
  the card, duplicates collapsed, Do Not Disturb, a day of history, keyboard
  control. rc2 slides them in from under the bar and out the same way.
- **Motion (rc2):** panels grow out of the bar and morph into each other;
  press feedback on buttons and bar icons.
- **Backgrounds:** video wallpapers (OWE) with a still frame on the lock
  screen; themes play a short silent intro; the wallpaper is remembered per
  theme.
- **Speed:** the theme picker opens immediately; the desktop reacts to
  changes instead of polling.
- Against our rules: a passwordless-sudo duration setting, and themes
  installed from git URLs at runtime.

## How it is built

- **One Quickshell process** (`shell/shell.qml`) owns bar, menu, image picker,
  notifications, lock, polkit, OSD, dock, idle and background. The base
  package list has `quickshell`, `owe` and `omarchy-screensaver`; Walker,
  Elephant, Waybar and Mako are gone.
- **Menu as data:** `shell/plugins/menu/Menu.qml` + `MenuModel.js` render the
  tree in `default/omarchy/omarchy-menu.jsonc` (user overlay in
  `~/.config/omarchy/extensions/`). Rows carry batched shell checks
  (`when`, `checked`); providers fill dynamic lists. The same menu is the
  system dmenu.
- **No settings screens:** Setup > Monitors, Keybindings and Input open the
  Hyprland `.lua` files in an editor.
- **Themes:** `themes/<name>/colors.toml` + backgrounds, preview and unlock
  art. `bin/omarchy-theme-set` renders templates into a staging directory,
  swaps it in atomically, recolors what is on screen first and the rest
  after, runs a hook, and drops outdated recolors (lock + generation counter).
- **Shell tokens:** `shell.toml` has one section per surface (bar, menu, lock,
  notifications, image picker) feeding the `Color` and `Style` singletons; one
  `BorderSurface` primitive draws them.
- **Wallpaper:** a `current/background` symlink; `omarchy-theme-bg-set` asks
  the shell to switch, with a cover and slanted reveal
  (`shell/plugins/background/Background.qml`); a carousel image picker.
- **Screensaver:** `omarchy-screensaver` (Rust) animates ASCII branding on an
  overlay per display; the shell owns idle (screensaver at 150 s, lock at
  300 s) and dismissing the screensaver cancels the lock.
- **Hyprland ties:** 12 QML files import `Quickshell.Hyprland`, including
  `Commons/Style.qml` (reads corner rounding and animations from `hyprctl`),
  `Ui/PopupCard.qml` (focus grab) and the notifications service. Menu, image
  picker, lock and background do not. OWE is Hyprland-only.

## Read for us

Omarchy feels coherent because one process draws every surface from one token
set and one set of components, one menu reaches everything with the same row
behaviour, and changes are choreographed as single events. Its contracts
(surface tokens, theme bundles, the switch transaction, menu as data) fit our
direction. It is not a model for designed settings screens: it has none.
GNOME Settings and macOS System Settings remain the reference for those.
